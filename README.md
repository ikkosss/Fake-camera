# Via + галерея вместо камеры

Патч браузера **Via 7.3.3 (20260823)**, `mark.via.gp`. Когда страница запрашивает съёмку
с камеры, открывается не камера, а галерея устройства: выбранное изображение уходит на сайт
так, как будто его только что сняли.

## Готовый APK

[`dist/Via_7.3.3_fakecam.apk`](dist/Via_7.3.3_fakecam.apk)

APK подписан новым ключом, поэтому поставить его «поверх» установленного из Google Play Via
не получится — сначала удалите оригинал.

## Что именно меняется

Сайт может получить снимок двумя разными способами, и перехватываются оба.

### 1. Живая камера в странице: `getUserMedia()` (WebRTC)

Так работают проверки личности, сканеры документов, «сделайте селфи» — страница показывает
видоискатель прямо внутри себя. Никакого выбора файла там изначально нет.

В каждую страницу на старте загрузки внедряется
[`camera_shim.js`](patch/src/mark/via/fakecam/camera_shim.js). Он подменяет
`navigator.mediaDevices.getUserMedia`: вместо камеры открывается галерея, выбранное
изображение рисуется на `<canvas>`, и странице отдаётся `canvas.captureStream()` — для неё это
обычный работающий видеопоток с камеры. Дополнительно:

* `enumerateDevices()` сообщает о наличии камеры, иначе часть сайтов не доходит до съёмки;
* у видеодорожки подменены `label`, `getSettings()` и `getCapabilities()`;
* если сайт просит ещё и микрофон, звук берётся настоящий;
* на HTTP-страницах, где `navigator.mediaDevices` вообще нет, объект создаётся.

Внедрение идёт из `Lp4/j;->onPageStarted` и дублируется из `Lp4/c;->onProgressChanged` на
ранней стадии загрузки; скрипт защищён от повторной установки.

### 2. Загрузка файла с требованием съёмки: `<input type="file" capture>`

```html
<input type="file" accept="image/*" capture="environment">
```

Обычная загрузка файла (без `capture`) работает как раньше — со штатным диалогом выбора.

Такие запросы приходят в обфусцированный фрагмент браузера
`Lc8/s6;->X(ValueCallback, FileChooserParams)` (это `WebChromeClient.onShowFileChooser`).
В начало метода добавлен вызов `mark.via.fakecam.FakeCamera`:

* `FileChooserParams.isCaptureEnabled()` ложно — возвращается `false`, дальше идёт
  нетронутый оригинальный код Via;
* иначе запускается выбор изображения с тем же кодом запроса `0x6f`, который Via уже
  использует для своего файлового диалога, поэтому результат разбирает штатный обработчик
  через `FileChooserParams.parseResult()`.

Этим же путём пользуется скрипт из первого пункта: его скрытое поле выбора файла помечено
атрибутом `capture`, поэтому вместо диалога выбора сразу открывается галерея.

Какой экран галереи откроется, зависит от версии Android:

| Android | Способ |
| --- | --- |
| 13+ | системный фотопикер (`MediaStore.ACTION_PICK_IMAGES`) |
| ниже | галерея (`ACTION_PICK` по `MediaStore.Images.Media.EXTERNAL_CONTENT_URI`) |
| запасной вариант | `ACTION_GET_CONTENT` с типом `image/*` |

Если сайт просит именно видео, подставляется видеогалерея. Любая ошибка внутри хука
приводит к возврату `false`, то есть к обычному поведению браузера.

## Проверка

```bash
npm install puppeteer-core
CHROME=/usr/bin/google-chrome node patch/test/shim_test.js
```

Тест открывает страницу в настоящем Chromium, вызывает `getUserMedia()`, подставляет в
появившийся выбор файла картинку (левая половина красная, правая синяя), а затем снимает кадр
из полученного «камерного» потока и проверяет цвета пикселей.

## Сборка

```bash
./patch/build.sh
```

Скрипт распаковывает `Via_*_base_src.zip`, конвертирует метаданные APKTool M
(`apktool.json`) в формат Apktool (`apktool.yml`), компилирует `patch/src` в dex, переводит
его в smali, вставляет хук, собирает и подписывает APK в `dist/`. Apktool, baksmali и
Android SDK скачиваются при первом запуске в `~/.cache/via-fakecam`.

Состав каталога `patch/`:

| Путь | Назначение |
| --- | --- |
| `src/mark/via/fakecam/FakeCamera.java` | новый класс: открывает галерею и внедряет скрипт |
| `src/mark/via/fakecam/camera_shim.js` | подмена `getUserMedia` кадром из галереи |
| `tools/embed_js.py` | упаковка скрипта в строковую константу Java |
| `test/shim_test.js` | проверка подмены в настоящем Chromium |
| `stubs/androidx/fragment/app/Fragment.java` | заглушка для сборки: в APK методы AndroidX переименованы R8 (`getContext` → `I`, `startActivityForResult` → `P2`) |
| `tools/json2yml.py` | конвертер метаданных APKTool M |
| `tools/inject_hook.py` | вставка вызова хука в smali |
